# 源级地区归属

## Why
Clash 输出的地区分组只按节点名正则匹配。自建（static）源的节点名常常不含地区关键字，例如 `[derp] VLESS Reality — migrated`：它的服务器在香港，但会落进「🌐 其余节点」，生成的策略组变成「美国 + 其余节点」，而不是「美国 + 香港」。Workers 免费额度没有服务器 IP 归属地查询能力，节点名里也没有可推断的信息，只能由管理员显式声明。

## What Changes
- 源新增可选的「地区」属性（`hk`/`tw`/`jp`/`sg`/`us`/`eu`，空值=自动）。D1 `sources` 表加 `region` 列（migration 0005）。
- 管理 API 创建/编辑源时接受 `region`，非法值拒绝（400）；列表与详情原样返回。
- Clash 渲染：指定了地区的源，其全部节点归入该地区组，不再按节点名匹配；未指定的源保持原有正则行为。
- 管理页源表单增加「地区分组」下拉（默认「自动（按节点名识别）」），源列表增加「地区」列。

## 非目标
不做服务器 IP 地理定位，不新增地区种类，不改 base64 输出（无策略组），不改 KV 回源与节流行为，不改分流配置的源分组语义。

## 影响
- 需要在生产执行 `db:migrate:remote` 后再部署 Worker；旧行 `region` 为 NULL，行为与现在完全一致。
- 零额外 KV 读写，零额外上游请求。
