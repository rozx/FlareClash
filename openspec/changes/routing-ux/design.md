# 设计

## 信息架构
1. 页头：标题「分流规则」+ 一句话说明（从上往下匹配，命中即停）+ 状态徽章（默认规则 / 已自定义 / 未保存）。
2. 添加规则：多行输入框 + 匹配方式（自动识别/域名及子域名/仅该域名/包含关键词/IP 段/国家或地区 IP）+ 去向 + 添加按钮。
3. 规则列表：`# | 匹配方式 | 内容 | 去向 | 操作`，末行固定为兜底。
4. 测试网址。
5. 节点组（可选）：`<details>`，有组时默认展开。
6. 备份与导出（高级）：`<details>`，含 JSON 编辑/导入/导出、Hiddify 导出与说明、恢复默认。
7. 底部固定保存栏：仅在有未保存修改时出现。

## 自动识别
逐项判断，只在域名与 IP 段之间识别，不自动判为国家代码（`cn` 既可能是 `.cn` 后缀也可能是国家，交给显式选择）：
- 含 `://` 或 `/` 后跟路径的网址 → 取 hostname 再按域名处理；去掉开头的 `*.` 或 `.`。
- `a.b.c.d` 或 `a.b.c.d/n` → IP-CIDR（无掩码补 `/32`）；含 `:` 的 IPv6 → IP-CIDR6（无掩码补 `/128`）。
- 其他 → DOMAIN-SUFFIX。
选「IP 段」时按同样规则区分 v4/v6；其余显式类型原样使用。

## 校验与插入位置
新规则插到列表最前：Clash 按顺序匹配，排在 `GEOIP,CN` 之后的域名规则会被国内 IP 先截走，最前面最符合「我刚加的规则要生效」的预期。加入前用「新规则 + 现有草稿」调用 `/api/routing/validate`，服务端错误「第 N 条规则：…」中 N ≤ 新增数量时映射回对应输入项，提示「xxx：原因」；已存在的同类型同内容规则跳过并提示。校验通过后用服务端规范化后的结果替换草稿。

## 测试网址
客户端先把完整网址裁成 hostname 再调用 `/api/routing/preview`（服务端仍做规范化与校验）。命中序号对应的规则行加高亮并滚动到可见；未命中则高亮兜底行。保留「不做 DNS/IP/GEOIP 匹配」的说明，但缩成一行。

## 离开保护
- 关闭/刷新：`window.onbeforeunload` 在草稿有修改且页面仍是分流页时阻止。
- 站内切页：`app.js` 的 `route()` 在切换前调用当前页登记的 `page._canLeave()`；返回 false 时用 `history.replaceState` 还原 hash（不触发 hashchange，不重绘，不丢草稿）。

## 不变的部分
数据结构、API、服务端校验、Clash/Hiddify 输出均不变；仍是纯 DOM 构造（el()），无 innerHTML。
